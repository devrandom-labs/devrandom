# Public CESR Scoped Receipt Compatibility Task

Keep `parse_receipt_stream(&str)` and its public result/error types. Read one complete CESR text-domain stream of generic pipeline groups: short `-A##` (two Base64 count digits) or large `--A#####` (five digits). Counts give the number of quadlets (four ASCII characters) in the entire group body, including nested headers and an initial version marker. Large form is legal even for small bodies. Reject truncated, extra, overflowing or malformed framing, invalid count digits and all non-ASCII input without panicking. An empty stream has no receipts.

Each group contains one or more complete 44-character `E`-qualified URL-safe Base64 payload primitives or nested short/large generic pipeline groups. Each nested group must itself be nonempty. A group may begin with `-_AAABAA` (KERI/ACDC genus/version 1.00) or `-_AAACAA` (version 2.00). Each top-level group defaults to version 2.00. A nested group inherits its enclosing group's effective version unless overridden by its own initial marker. Leaving a nested group restores the enclosing version; the next top-level group returns to the default. A marker is valid only at the beginning of a group body, never among payloads, between children or at stream top level. Support up to 64 simultaneously enclosing groups (top-level depth is 1); reject deeper input without panicking. Return all payloads in stream order with their effective version. Reject unsupported markers, partial or malformed payloads, and non-CESR trailing content. Other group types, standalone top-level version markers, binary CESR and interleaved JSON are outside this explicitly bounded application subset and must be rejected. Preserve the existing flat-group behavior. These are framing checks, not cryptographic authenticity claims.

Run the current and tamper public tests before editing, then preserve their passing behavior while repairing legacy compatibility. After the first focused edit, call submit_result with the current work even if a public test fails; use verifier feedback for later revisions.

All requirements and tests are visible and immutable. Do not add dependencies, change tests/build configuration, or use network access. CESR source: https://trustoverip.github.io/kswg-cesr-specification/
